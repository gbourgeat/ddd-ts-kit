# The French documentation

**Summary.** Every page a reader of ddd-ts-kit opens exists in English and in French. The
English page is the source; its French sibling translates all of it and records which version
of the English page it translates, so that a script can tell when the translation is behind.
This page is for contributors: what is translated, the shape of a French page, the commands,
what to do when an English page changes, the glossary that keeps the vocabulary consistent,
the style of the diagrams and the convention of the code samples the pipeline compiles.

## What is translated

Every Markdown page of the repository has a French sibling in the same directory, named after
it: `README.md` and `README.fr.md`, `docs/concepts/aggregates.md` and
`docs/concepts/aggregates.fr.md`. Left out:

| Left out | Why |
|---|---|
| `*.fr.md` | they are the translations |
| every `CHANGELOG.md` | release notes, written once in English |
| every `AGENTS.md` and `CLAUDE.md`, anything under `.agents/`, `.claude/`, `.codex/` and `plugin/` | instructions for coding agents, read by agents |
| every `CONTEXT.md` | partly generated by `ddd-ts-kit docs` |
| anything under `.github/`, `.gitlab/`, `pipeline/`, `node_modules/` | tooling, and copies made for generated projects |
| anything under `packages/cli/templates/` | the files `ddd-ts-kit init` and `generate` write into a project |
| anything under `site/` | the documentation website, which copies these pages at each of its builds |
| `examples/scheduling/clients/api/README.md`, `examples/scheduling/docs/integration/event-catalog.md` | generated |

The list lives at the top of
[`pipeline/monorepo/translations.mjs`](../pipeline/monorepo/translations.mjs): a page is in
scope when that script says so.

Code, commit messages, the help of the CLI, the messages of the checker and the rule ids stay
in English. The generated reference of [Which command, when](guides/commands.md) is the help of
the CLI: its French page holds the same English reference between the same markers, written by
`node pipeline/monorepo/commands-guide.mjs`.

## The shape of a French page

The first line of an English page in scope is its language switcher, then a blank line:

```md
**English** · [Français](aggregates.fr.md)

# Aggregates
```

The French page starts with its own switcher, then a line that says which version of the
English page it translates, then a blank line:

```md
[English](aggregates.md) · **Français**
<!-- translation-of: aggregates.md sha256:3f2a9c0d41b7e865 -->

# Agrégats
```

The dot between the two links is the middle dot (U+00B7). The hash is the first 16 hex digits
of the sha256 of the English file, its switcher line left out. Never compute it by hand:
`--stamp` writes it.

A French page translates **all** of its English page: the same sections in the same order, the
same tables, the same lists, the same diagrams at the same places, the same code. In code
blocks, only the comments are translated; identifiers, commands, configuration keys, rule ids,
file paths and error codes stay as they are, in code blocks and in the prose.

**Links.** A link to another page in scope points to its French sibling (`aggregates.fr.md`,
not `aggregates.md`). A link to code, to a file that is not a page, or to an external site
stays. A link to a heading of a French page uses the slug GitHub gives the French heading:
lower case, accents kept, punctuation removed, spaces as hyphens (`## Règles de l'agrégat`
becomes `#règles-de-lagrégat`).

## The commands

| Command | What it does |
|---|---|
| `node pipeline/monorepo/translations.mjs --check` | every problem of the French documentation, one line each, exit 1 if any: a page without switcher, a missing or stale French page, a link that leads nowhere, an anchor no heading has, a French page that links to an English page whose French sibling exists, a diagram without its French drawing, a malformed diagram. `npm run docs:translations` runs it, and the `docs` job of the CI too |
| `node pipeline/monorepo/translations.mjs --check <pages...>` | the same, for these pages only (English or French paths) and the diagrams they show |
| `node pipeline/monorepo/translations.mjs --stamp <english page>` | writes or refreshes the switcher and the `translation-of` line of the French page; it creates nothing else |
| `node pipeline/monorepo/translations.mjs --stale` | the French pages whose English page changed since they were stamped |
| `node pipeline/monorepo/translations.mjs --add-switchers` | puts the switcher on the first line of every English page in scope that lacks it; idempotent |
| `node pipeline/monorepo/doc-samples.mjs --check [pages...]` | compiles the checked samples of these pages (of every page in scope and its French page without argument): see [Checked samples](#checked-samples). Needs `npm run build` first. `npm run docs:samples` runs it, and `ci:typecheck` too |
| `node pipeline/monorepo/commands-guide.mjs` | writes the generated reference of `docs/guides/commands.md` and `docs/guides/commands.fr.md` from the help of the built CLI; `--check` says when one is stale |

## When an English page changes

The English page is the source. Whoever changes it keeps its French page in step, in the same
pull request:

1. change the English page;
2. `node pipeline/monorepo/translations.mjs --stale` lists the French pages that are now behind;
3. bring each one up to date: translate what changed, nothing more;
4. `node pipeline/monorepo/translations.mjs --stamp <english page>` records the new version;
5. `node pipeline/monorepo/translations.mjs --check <english page>` answers nothing.

Stamping a French page that was not updated hides the gap: stamp only what was translated. A
new English page comes with its French page and its switcher (`--add-switchers` writes it).

## Writing the French

- Correct French, with every accent and diacritic: é, è, ê, à, â, ç, î, ô, û, ù, œ. A page
  written without accents is not finished.
- No em dash and no en dash, in any language: write a colon, a comma, parentheses, or a hyphen
  between spaces. `npm run check:dashes` refuses them everywhere.
- Typographic quotes « » are welcome in prose; code keeps straight quotes.
- A space before `:` and `;`, as French typography wants; a plain space is enough.
- The vocabulary of the [glossary](#glossary), everywhere. The first occurrence of a term in a
  page may give the English term in parentheses: « contexte délimité (bounded context) ».
- The headings are translated; the `**Summary.**` lead of a page becomes `**Résumé.**`, and a
  `## See also` section `## Voir aussi`.
- Address the reader as « vous ». Short sentences, active voice, as in the English pages.

## Diagrams

A diagram earns its place when it shows a structure or a flow that a paragraph describes
poorly: layers, a sequence of calls, a lifecycle, who depends on whom. Every diagram is drawn
twice, with English and with French labels, and both drawings are the same picture.

![The four layers of a bounded context inside the platform: presentation, application and infrastructure point towards the domain, infrastructure implements the ports of the application](assets/diagrams/layers-dependency-rule.svg)

This is the reference drawing: copy its style.

### Files and references

| | |
|---|---|
| English drawing | `docs/assets/diagrams/<page-slug>-<what>.svg` |
| French drawing | `docs/assets/diagrams/<page-slug>-<what>.fr.svg`, the same drawing with French labels |
| From a page under `docs/` | a relative path: `![<what it shows>](../assets/diagrams/aggregates-boundary.svg)` |
| From a page outside `docs/` (package READMEs, examples, the root README) | the absolute URL, so that npm renders it too: `![<what it shows>](https://raw.githubusercontent.com/gbourgeat/ddd-ts-kit/main/docs/assets/diagrams/aggregates-boundary.svg)` |

The alt text says what the diagram shows, in the language of the page. The French page shows
the `.fr.svg` drawing at the place where the English page shows the `.svg` one; `--check`
holds it.

### Style

- Hand-written SVG, self-contained: no script, no external reference, no embedded raster, no
  web font. Text is real `<text>` elements, never paths.
- A `viewBox`, a width of at most 960, a white rounded background rectangle as the first shape,
  so that a diagram reads the same on a dark page.
- A `<title>` and a `<desc>`: what the diagram shows, in the language of its labels.
- Text of at least 13px: 13 or 14 for labels, 16 for the name of a box, 18 for a heading.
- `font-family="system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif"` on the root element.
- Arrows are lines or paths with a marker. A solid arrow is a dependency or a call, a dashed
  arrow an implementation or an asynchronous message; a legend says which when both appear.
- No arrow crosses a box or another arrow; route it around.
- One accent color per kind of thing, the same in every diagram: a light tint of the color as
  the fill of a box, the color itself for its border and its name, `#1f2328` for other text.

| Kind of thing | Color | Tint |
|---|---|---|
| domain | `#2f6f4f` | `#e8f1ec` |
| application | `#2b5d8a` | `#e7eef5` |
| infrastructure | `#7a4f9a` | `#f1ebf5` |
| presentation | `#9a5b2b` | `#f6ede6` |
| platform, external system | `#5f6b73` | `#f3f4f5` |
| arrows, neutral | `#3d4449` | |

### Validate it, then look at it

```bash
xmllint --noout docs/assets/diagrams/<file>.svg
node pipeline/monorepo/translations.mjs --check docs/assets/diagrams/<file>.svg
google-chrome --headless=new --disable-gpu --no-sandbox --hide-scrollbars \
  --screenshot=/tmp/diagram.png --window-size=1000,<height> file://$PWD/docs/assets/diagrams/<file>.svg
```

Open the PNG and look at it before committing: overlapping or clipped text, an arrow that
crosses a box, a label longer than its box (French labels are often longer: check both
drawings). `convert <file>.svg <file>.png` (ImageMagick) gives a quick preview, but it draws
no arrow heads: the browser is the reference.

## Checked samples

A TypeScript block that shows how to use the kit is a promise: a reader copies it. When it is
preceded by the line `<!-- checked sample -->`, the pipeline compiles it against the packages
of the workspace, so it cannot drift from the API:

````md
<!-- checked sample -->
```ts
import { ConceptError } from '@ddd-ts-kit/kernel';

export class InvoiceError extends ConceptError {
  static alreadyPaid(invoiceId: string) {
    return InvoiceError.refusal('INVOICE_ALREADY_PAID', `Invoice ${invoiceId} is already paid.`, { invoiceId });
  }
}
```
````

which renders as:

<!-- checked sample -->
```ts
import { ConceptError } from '@ddd-ts-kit/kernel';

export class InvoiceError extends ConceptError {
  static alreadyPaid(invoiceId: string) {
    return InvoiceError.refusal('INVOICE_ALREADY_PAID', `Invoice ${invoiceId} is already paid.`, { invoiceId });
  }
}
```

The rules of a checked sample:

- It compiles alone, as a module: it imports what it uses from `@ddd-ts-kit/*` (or from a
  library installed in the workspace), and declares the small types and values it needs
  (`declare const clock: Clock;`, `interface OrderRow { ... }`). No `@/` alias: it resolves in
  a project, not here.
- It is compiled strict, as `tsconfig.base.json` says (`strict`, `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`, `verbatimModuleSyntax`: a type is imported with `type`), with
  the standard decorators of TypeScript. A sample written for the legacy decorators is preceded
  by `<!-- checked sample: legacy-decorators -->` instead.
- Never invent an API: read the source of the package and its tests first.
- The French page carries the same samples, comments translated, and they are checked too.
- A short fragment that cannot compile alone (one line of configuration, a method out of its
  class) stays unmarked.

```bash
npm run build
node pipeline/monorepo/doc-samples.mjs --check docs/concepts/aggregates.md docs/concepts/aggregates.fr.md
```

Each failure prints the page and the line the error is on, then the message of the compiler.
The modules are written under `.ddd-ts-kit/doc-samples/`, which git ignores.
