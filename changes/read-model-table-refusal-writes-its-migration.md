**Breaking: `ReadModelTableNotReadyError` says what is missing and writes the migration, for the columns its store maps and no other, and is built from a `ReadModelTableState`.** Its message named the table and the columns that refuse NULL, then gave the statement to write with a `<column>` to fill in. It now names the table, each thing that keeps it from holding a trace, and the whole migration as PostgreSQL statements, also in its `statements` field. The state it reports is the reading of the store (`PostgresTraceColumns` of `@ddd-ts-kit/kernel`, behind the tables of `@ddd-ts-kit/knex`, `@ddd-ts-kit/drizzle`, `@ddd-ts-kit/prisma` and `@ddd-ts-kit/typeorm`), which looks at the columns the store maps as fields of its row and at nothing else: the key, the tenant column whatever its name, the stamp and a column the store does not map are never read, never altered and never emptied. Among the mapped columns it tells those that refuse NULL (`refusing`) from those no migration opens (`unfit`: a part of the primary key, an identity column, a generated column, a column that is not there), and says when the table itself is not in the database; a store whose mapped column is unfit refuses, with no statement for that column, where it failed later on the database. The stamp columns carry the names the definition of the store gives them, so a renamed `deleted` column is the one the migration names.

The migration quotes every identifier, opens each refusing column (`alter table ... alter column ... drop not null`), then drops the constraint `<table>_live_rows_whole` if it exists, adds it `not valid` and validates it in a statement of its own (`validate constraint`, which lets readers and writers through while it reads the table), and last empties the rows deleted before with an update that touches only the rows still holding a value. It can be run twice. On a large table, run `validate constraint` and the update in transactions of their own: the message says so. The name of the constraint is cut at 63 bytes, as PostgreSQL cuts it, not at 63 characters. A constraint that is there but not validated, or that checks something else than the mapped columns, is read (`pg_get_constraintdef`) and reported as a warning by `ReadModelTables`, not as a refusal: the table holds a trace all the same, and a row may require no field. A refusal read from a definition alone (Drizzle, TypeORM, a column declared not null there) carries no statement and says to declare the column nullable.

To move: code that builds the error itself (a `ReadModelRows` of your own) passes a state, `new ReadModelTableNotReadyError({ table, exists: true, refusing, unfit: [], row, deleted: 'deleted' })` (`schema` and `constraint` when known), where it passed `(table, columns)`; a test that compared the whole message compares `table`, `columns` or `statements`. A read model whose store maps a part of its primary key, an identity column or a generated column as a field of its row is now refused before its first trace: take that column out of the fields the store maps, or make it an ordinary nullable column.
