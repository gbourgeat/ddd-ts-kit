**`ddd-ts-kit merge-trunk` no longer drops the work of a branch when `--since` names a commit the trunk does not hold.** The merge is computed from `--since`: named too new, every file the branch added before it read as deleted by the trunk, the merge removed it without a conflict, and the report said `lost lines: none lost`. `--since` at the head of the branch is now refused (exit 2), since the result would be the trunk alone. `verify-merge`, which `merge-trunk` runs before its commit, reads the files a side added since the two sides parted (`git merge-base`), whatever base the merge was computed from: one the result lacks, while no commit of the other side touched its path, is reported under `files deleted by the merge` and stops the merge. A file the result holds under another path is not reported.
