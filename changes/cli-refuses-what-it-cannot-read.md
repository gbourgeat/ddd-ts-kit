**The CLI refuses an input it cannot read instead of reading it as something else.** Every ref a command takes is resolved to its commit with `git rev-parse --end-of-options` before any other git command reads it, so that a value starting with a dash is never taken for an option of git: `affected --base=--output=<file>` emptied that file and printed `Nothing that runs is affected`, so `--run test` ran nothing, and `verify-merge` could hand such a value to `git log`. A ref that names no commit is refused with exit code 2 (`<ref> is not a commit of this repository`) by `check --changed-since`, `cited --base` and `--removed-since`, `verify-merge <commit>`, `--since`, `--theirs` and `--base`, `verify-slice --since` (before any step runs), `merge-trunk --trunk` and `--since`, `mutation --changed`, `worker-scope`, `story-scope` and `worktree --base`, and `drizzle-generate --replay --base`. `affected` still selects everything for a `--base` or `--head` that names no commit, which the pre-push hook of a clone without `origin/HEAD` relies on, and refuses one that starts with a dash. A context named after what every JavaScript object has (`constructor`, `prototype`, `__proto__`, `toString`, `hasOwnProperty`, `valueOf`) is refused by `init --context` and `generate context` with the reason, and such a name is an unknown command or an unknown context everywhere else: `init --context constructor:core` failed on `entry.upstreams is not iterable`, and `ddd-ts-kit toString` printed a stack trace. A fault of the kit itself now exits with code 4, never 1, which is for violations: one line on stderr, `internal error of ddd-ts-kit <version>: <message>; please report it at https://github.com/gbourgeat/ddd-ts-kit/issues with the command: ddd-ts-kit ...`, and under `--json` the JSON of an error marked `"internal": true`, instead of the stack trace of Node. A context or a module named with what the kit would drop to read it is refused with what it would have read, where it was rewritten silently: `generate context ../evil` planned `src/contexts/evil`, `generate context Évil` planned `src/contexts/vil`, and `generate aggregate ../billing Invoice` worked in `billing` (`` `../evil` is not a name: a context is named in letters, digits and dashes, and the kit would have read `evil` in it ``); the case and the separators `-`, `_` and spaces still change freely. This holds for `init --context`, `generate context` and its `--upstream`, the context of every generator, `generate module`, `--module`, `--group`, `move-to-module` and `context-layout`.

To move: a script that passed a ref that is not a commit now stops with exit code 2: fetch the ref or fix its name; so does one that passed a name the kit rewrote (`../billing`, an accented letter): write the name as the config declares it. A script that read exit code 1 as any failure reads 4 too: 1 now means violations only.
