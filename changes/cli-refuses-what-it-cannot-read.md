**The CLI refuses an input it cannot read instead of reading it as something else.** Every ref a command takes is resolved to its commit with `git rev-parse --end-of-options` before any other git command reads it, so that a value starting with a dash is never taken for an option of git: `affected --base=--output=<file>` emptied that file and printed `Nothing that runs is affected`, so `--run test` ran nothing, and `verify-merge` could hand such a value to `git log`. A ref that names no commit is refused with exit code 2 (`<ref> is not a commit of this repository`) by `check --changed-since`, `cited --base` and `--removed-since`, `verify-merge <commit>`, `--since`, `--theirs` and `--base`, `verify-slice --since` (before any step runs), `merge-trunk --trunk` and `--since`, `mutation --changed`, `worker-scope`, `story-scope` and `worktree --base`, and `drizzle-generate --replay --base`. `affected` still selects everything for a `--base` or `--head` that names no commit, which the pre-push hook of a clone without `origin/HEAD` relies on, and refuses one that starts with a dash.

To move: a script that passed a ref that is not a commit now stops with exit code 2: fetch the ref or fix its name.
