**`imports/alias-only` lets a file directly under `test/support/` import its neighbour by `./<name>`.** A test runner loads its global setup, and every file that one imports, with the resolution of Node, before any alias of the project exists: Jest applies no `moduleNameMapper` there. A global setup made of several files could therefore import them by alias only when the runner was started under a loader that resolves aliases, and failed with `Cannot find module '$test/support/...'` from `npx jest` or from the runner of an editor. The rule, in `ddd-ts-kit check` and in `@ddd-ts-kit/eslint-plugin`, now leaves that one relative path alone: from a file directly under `test/support/`, a specifier `./<name>` with no further directory. Nothing else changes: from `test/support/`, `../e2e/support/start-application` and `./parts/part` are reported and fixed to the alias, and a file of any other directory still imports its neighbour by alias. Under `"importExtension": "js"` the neighbour is named by the `.ts` of its source (`./test-database-run.ts`), which Node resolves, and `init` writes `"rewriteRelativeImportExtensions": true` in the `tsconfig.json` of such a project so that the compiler reads it. See [Import aliases](docs/tools/import-aliases.md).
