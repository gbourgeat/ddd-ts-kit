**`ddd-ts-kit generate file-upload --text <utf-8|single-byte>` writes the upload of a text file, with a spec that sends one that is not UTF-8.** Without the flag the generated controller still declares a document (PDF, PNG, JPEG). With it, the upload is a CSV under the names browsers give one (`text/csv`, `application/csv`, and `application/vnd.ms-excel` stated as `text` in `contentRules`), held to the text rule asked: `single-byte` when the file may be in Windows-1252 or ISO-8859-1 as well as UTF-8, `utf-8` when it must be UTF-8. The spec of the controller, a controller of the kit or a Nest controller, then sends a multipart form through `multipartUploads()` of `@ddd-ts-kit/http/uploads`: under `single-byte` a Windows-1252 file reaches the command byte for byte, under `utf-8` it is answered 415, and under both a workbook under the name of a CSV is answered 415. The spec of the handler stages a CSV. Another value of `--text` is refused with the two it takes. See `docs/concepts/file-storage.md`.
