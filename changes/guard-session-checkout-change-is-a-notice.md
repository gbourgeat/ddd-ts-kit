**A file the conductor changes in its own checkout no longer stops its workers.** When a file of the checkout of the session was left changed while the last command of a worker ran, the guard of the plugin refused the next call of that worker once and told it to stop, though the file was written already and the worker may put nothing back there: each edit of the plan by the conductor stopped the workers running. The call now passes, and the worker is told once, as context of the call, to put nothing back there and to name the files in its report for the conductor; the stop of the worker still carries it to the conductor. A change of the packages the guard runs (`node_modules/ddd-ts-kit`, Biome) still refuses the next call once, and so does a change of what the guard stands on in that checkout: `ddd-ts-kit.config.json`, the settings, hooks and plugins of a coding agent (`.claude/`, `.codex/`, `.agents/`, `.github/hooks/`, `.github/copilot/`) and a scope file under `.ddd-ts-kit/`. A guard switched off in the checkout of the session no longer lifts a pinned worker there: its guard keeps the mode of its first call in every checkout of the repository.
