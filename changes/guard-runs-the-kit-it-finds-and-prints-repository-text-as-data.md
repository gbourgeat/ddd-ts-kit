**The guard runs only the kit and the Biome a project installed, and prints what it reads from the repository as data.** The CLI the guard runs at session start, after each write and at stop is the bin that the manifest of `node_modules/ddd-ts-kit` names, run with Node, in the project or hoisted to a parent folder no higher than the top of its repository; a `node_modules/.bin/ddd-ts-kit` that is no bin of that package, or one above the repository (`/tmp/node_modules`), is never run, and the session says the CLI is not installed. With `formatOnWrite`, Biome is the bin of `node_modules/@biomejs/biome`, run the same way. The next step of the plan is said as `Plan (docs/architecture/plan.md): "<text>"`, on one line, without backquotes, cut to 300 characters and never opening with `ddd-ts-kit:`; the next step of a story, of its build gate and of its stop are quoted the same way, and a story id, a branch, a worktree, a context or an agent id the CLI reads from the repository is repeated only when it follows its grammar. The state of the guard, the run and the report of a worker are written through no symbolic link, and not at all when `.ddd-ts-kit` itself is a link. A `guard` mode other than `off`, `advise` and `enforce` is read as `enforce`, at pre-write and at stop alike, and the session start says so; the version gap is read beside the CLI that runs; only the plugin's `ddd-ts-kit:context-builder` is counted and recorded (an agent of the project named `context-builder` keeps the scope of its worktree). The config is read once per hook, at most 256 KB (above, the session says so and the guard judges nothing there), each field it uses of the type it expects or its default, a context named `constructor` or `__proto__` like any other. Pre-write runs the refusals that start no process before those of the CLI and the git notes of a worker; a session start gives the CLI 10 s in all and says when it was cut short; a `check` that times out at stop says so; post-write checks the first five files of a patch and names the others. The markers of what was said once live in `.ddd-ts-kit/guard/markers/` of the project, not in the temp directory, and go after a week, with the state of the builders; a new run of a builder drops the note its last run left before inline code. The hooks description and the guide say the guard is a guide, not a security boundary, that it runs the project's own CLI and Biome from node_modules, and that writes outside the worktree of code it cannot read are not enumerated.

To move: a project whose CLI is hoisted above the top of its repository (a workspace whose root is not the repository) installs `ddd-ts-kit` inside the repository; a project whose `guard` mode is misspelt (`"enforced"`) writes `enforce`, `advise` or `off`.
