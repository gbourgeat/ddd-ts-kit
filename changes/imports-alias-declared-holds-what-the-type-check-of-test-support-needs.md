**Breaking: under `"importExtension": "js"`, `imports/alias-declared` reports a `tsconfig.json` that does not let the type check read the `.ts` by which a file of `test/support/` names its neighbour; it reports a build configuration that would write nothing, and `ddd-ts-kit build-aliases` refuses one.** The files a test runner loads as its global setup import one another by `./<name>.ts` in such a project. The compiler refuses that ending (`TS5097`) unless `tsconfig.json` sets `"allowImportingTsExtensions": true`, which it accepts only in a configuration that emits nothing (`"noEmit": true`), and a `tsconfig.build.json` that extends it without setting both back to `false` compiles without an error and writes no file: `build-aliases` then finds no output, or rewrites an earlier one. `init --import-extension js` writes those four lines, and `ddd-ts-kit check` now holds them: it reports `tsconfig.json` when a file directly under `test/support/` names a neighbour by its `.ts` and neither `allowImportingTsExtensions` nor `rewriteRelativeImportExtensions` is set there, and, whatever `importExtension` is, `tsconfig.build.json` and each tsconfig a script of `package.json` compiles what ships with (`tsc -p tsconfig.prod.json`, `tsc` alone for `tsconfig.json`) when it resolves `noEmit` as `true`, or `allowImportingTsExtensions` as `true` without `rewriteRelativeImportExtensions` or `emitDeclarationOnly`. Each finding names the lines to write. An `extends` is followed as the compiler follows it: a relative path with or without its `.json`, and a package installed in the `node_modules` of the project root; a package found through its `exports`, or in a `node_modules` above the root, is not. `ddd-ts-kit build-aliases` refuses, exit 2, a tsconfig that resolves `noEmit` as `true`: the compiler wrote nothing with it, and the command used to answer `rewritten 0 alias specifier(s)` over an earlier output, which then shipped. The compiled output is what it was: no option rewrites an import of the sources, so no helper is added to it. A project that writes its imports without an extension (`"importExtension": "none"`, the default) is given none of these options by `init`, and is reported only for a `noEmit` it wrote itself in a configuration its build inherits.
