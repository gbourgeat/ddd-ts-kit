**`advisoryLock` and `tryAdvisoryLock` serialise the units of work that decide on the same business key, on the four ORM.** A decision taken on rows that do not exist yet (count then insert, the next number of a sequence per tenant) has no version for optimistic concurrency to compare, and took a raw `pg_advisory_xact_lock` that `tenancy/scoped-statement` refuses. `@ddd-ts-kit/knex`, `@ddd-ts-kit/drizzle`, `@ddd-ts-kit/prisma` and `@ddd-ts-kit/typeorm` now export the same two functions: `advisoryLock(context, key, { tenant: scope })` waits until no other transaction holds the lock on `key` and holds it until the unit of work commits or rolls back, and `tryAdvisoryLock` answers `false` instead of waiting. The key is a text that PostgreSQL hashes into 64 bits (`hashtextextended(text, 0)`); with `tenant` it is `tenant:<id>:<key>` (`tenantKey`), so two tenants never wait for each other and work that names no tenant is refused; two keys of the same hash wait for each other, and nothing else happens. Outside a unit of work the lock would be released at once: `AdvisoryLockOutsideUnitOfWorkError` of `@ddd-ts-kit/kernel`. `tenancy/scoped-statement` accepts the helper, which is given the context and never the executor, and a raw advisory lock is still reported, with a message that now names the helper. `advisoryLockContract` of `@ddd-ts-kit/testing` holds the four packages to the same behaviour; the wait of a second unit of work runs on a real PostgreSQL (`concurrent: true`), PGlite being one session. PostgreSQL only. The page is "A decision no version protects" in `docs/tools/persistence.md`.

To move: nothing has to. A raw `pg_advisory_xact_lock` kept under a `ddd-ts-kit-disable-next-line tenancy/scoped-statement` becomes `await advisoryLock(context, key, { tenant: scope })`, and its suppression goes: `ddd-ts-kit check --rule tenancy/scoped-statement` lists what is left. The number locked on changes with the helper (the hash of the text, with the tenant in it): deploy the change to every instance at once, or two versions of the application would not wait for each other.
