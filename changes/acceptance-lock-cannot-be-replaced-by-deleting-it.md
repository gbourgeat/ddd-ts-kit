**`ddd-ts-kit acceptance <story> --lock` no longer takes a changed scenario without a verdict when the lock file was deleted first.** With no lock file on the disk, `--lock` reads the last lock of the story that a commit holds and compares with it as with the lock on the disk: a scenario, a criterion or a regression test that differs without an `amend` verdict of the `acceptance-judge` agent for its very version is refused (exit 2, naming it, with `git checkout -- <lock>` to restore the lock), and the verdicts it finds are kept as amendments of the lock. Outside a git repository the story is locked and one line says the previous lock could not be checked.
