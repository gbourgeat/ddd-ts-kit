**`InMemoryEventBus` rethrows the failure of a single handler as it is, instead of wrapping it in an `AggregateError`.** Every handler of an event still runs when one fails. When exactly one failed, `publish` now rejects with that error, so its class and its `code` reach the caller: a `CONCURRENCY_CONFLICT` raised in a handler is answered 409 by the default mapping of `@ddd-ts-kit/http`, the outbox relay stores that code as `lastErrorCode` instead of `AggregateError`, and an end-to-end spec sees it. When several failed, `publish` rejects with an `AggregateError` holding them, as before; its message is now `<n> event handlers failed`.

To move: code or a spec that catches the rejection of `publish` on the in-memory bus as an `AggregateError` (`rejects.toThrow(AggregateError)`, `error.errors[0]`) when one handler failed now receives the error of that handler itself: assert or read that error, and keep `AggregateError` for the case where several handlers fail.
