**In the declared style, the declarations of a context are written per layer: a role folder holds its role files and nothing else.** With `"stack.assembly": "barrel"`, `generate`, `docs` and `npm run dev` write one `<layer>.declarations.ts` directly in each layer of a context that holds a declared role file, `application/application.declarations.ts`, `infrastructure/infrastructure.declarations.ts` and `presentation/presentation.declarations.ts`, and the same in each module of the model (`application/<module>/application.declarations.ts`), instead of one `<folder>.declarations.ts` in every role folder. A folder that held one job, one adapter or two use cases no longer holds a generated file beside them, and a context reads as its role files. `<context>.declarations.ts` still re-exports these files, so the composition root, `contextModule(...)` and the worlds of the tests import it as before. Each file keeps the same content, for its whole layer: the imports, one `export *` per role file sorted by path, then the `injected(Class, [Tokens])` of the classes that take something. `declarations/barrel-current` compares the files of the layers and reports the `<folder>.declarations.ts` of a role folder left next to them; the guard of the plugin, `tree/closed`, `clean/one-export-per-file`, `clean/file-size`, the commit size and `merge-trunk` treat the layer files as generated, like the others. Under `"stack.assembly": "discovery"` nothing changes.

To move: run `npx ddd-ts-kit docs` (or any `generate` without `--local-only`, or `npm run dev`), which writes the declarations of each layer, deletes the files of the role folders and rewrites `<context>.declarations.ts` as their summary, and commit the result. Upgrading alone fails nothing: for one minor version, a context still declared in one file per role folder, exactly as 0.85 and 0.86 would write them for the current role files and constructors, is accepted. `ddd-ts-kit check` reports it as a warning of `declarations/barrel-current` (exit 0) that says how to move, `docs --check` passes and prints the same warning, and `generate --local-only` leaves it as it is and says so in a note. The single `<context>.declarations.ts` of 0.84 is still accepted in the same way. A later minor version reports both as errors.
