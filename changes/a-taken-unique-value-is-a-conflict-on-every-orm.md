**A save that takes a value a unique constraint keeps (an email) is refused as `CONFLICT` on the four ORM, not as a lost update or a 500.** The first save of an aggregate ignored any conflict on Drizzle, Prisma and TypeORM, so a new aggregate with a taken email wrote nothing and `optimisticUpdate` raised `ConcurrencyError`, a 409 `CONCURRENCY_CONFLICT` that a client retries for nothing; on Knex the driver error went through as a 500. Now the first save ignores a conflict on the id alone (`onConflictDoNothing({ target })` on Drizzle, `insertIgnoringConflict` of `@ddd-ts-kit/typeorm` on the primary key, as on Knex), Prisma, whose `skipDuplicates` names no target, tells a taken id from another value with `rowsCreated` of `@ddd-ts-kit/prisma`, and `optimisticUpdate` raises the new `UniqueViolationError` of the kernel, a `ConflictError` (code `CONFLICT`, 409) whose `cause` is the error of the driver (`23505`, `ER_DUP_ENTRY`, `SQLITE_CONSTRAINT_UNIQUE`, `SQLITE_CONSTRAINT_PRIMARYKEY`, a raw `SQLITE_CONSTRAINT` of libsql that names a unique key, `P2002`), on an insert and on an update alike. `repositoryContract` of `@ddd-ts-kit/testing` takes `createAggregateTaking` to prove it on an adapter over a table with a unique column. On MySQL, whose `INSERT IGNORE` names no conflict target, `insertIgnoringConflict` of Knex and of TypeORM asks whether a row holds the key when nothing was written, as `rowsCreated` does.

To move: a client that retried the 409 `CONCURRENCY_CONFLICT` of a taken value now gets a 409 `CONFLICT`; a handler that has its own refusal for it catches `UniqueViolationError`. A generated repository changes its first save: on Drizzle `.onConflictDoNothing({ target: <table>.id })`; on Prisma `insert` answers `rowsCreated(created, { id, holders: () => <table>.count({ where: { id } }) })` (with `...tenantWhere(this.scope)` on a tenant table); Knex and TypeORM need no change. `insertIgnoringConflict` of `@ddd-ts-kit/typeorm` ignores a conflict on the primary key only: a call that relied on it to skip a row for another unique constraint writes that statement with `.orIgnore()`.
