**What the generators write passes `format:check` as written, reads in the words of the glossary, and its specs state behaviour; `generate` refuses a flag its kind does not take.** A command on an aggregate without `--creates` wrote its one-parameter constructor over three lines, which `npm run format:check` (and so `verify`) refused right after the run: it is now on one line, and broken by the generator only when the names make it longer than the line width. `generate policy`, and `generate port`, take `--term`, as the refusal of a policy whose permission names a new word asks; `file-upload` shows it in its usage. A flag another kind takes and this one does not (`--term` on `route`, `controller` or `repository`, `--search` on `command`) was ignored without a word; it is now refused, with the usage of the kind, and the top usage of `generate` no longer lists `--term` as common to every kind. The fake of the reader of a query implements its port instead of extending the in-memory adapter, so `generate test-world` no longer says it implements no port (the fake of a search states its port too). The first `--term` given to a generator takes away the `TODO(domain)` of the glossary of `CONTEXT.md`, which `status` and `todo` counted as remaining. The specs of the model are described in the words of the glossary (`Invoice line`, `Invoice issued`, `Invoice numbering`, the value objects of the identity preset), and the spec of a policy by the question it answers (`Who may cancel an invoice`), so that `docs/behaviour` no longer shows two blocks titled after the use case. The spec of an integration handler no longer checks that an instance it built is an instance of its class, the spec of a domain service no longer asserts `Object.keys(...)` (it lists the decisions to test as `it.todo`), and the spec case of a refusal asserts its code and its facts, not its message. "does to a Invoice" and "a invoice number" take their article.
