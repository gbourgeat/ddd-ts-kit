**`ddd-ts-kit check` reports a read model store that the list of the read model tables does not answer for (`persistence/read-model-listed`).** The application checks the tables of its read models when it starts, and `npm run db:read-models` before a deployment, by the stores `src/platform/database/read-model-tables.ts` lists and no other: a store written by hand and never listed was checked by nothing, in silence. The new rule, an error, reads the stores of the tree and reports each one the list neither holds under its context (itself, or a class that extends it), nor names in `NOT_LISTED`, nor leaves out by a comment that holds `<context>: <Store>`; its fix gives the import and the entry to add. A store is a class of a context, tests aside, that is not abstract and extends `DrizzleReadModelStore`, `KnexReadModelStore`, `PrismaReadModelStore` or `TypeOrmReadModelStore`, directly or through classes of the project, wherever they are declared. It also reports an entry of the list whose class the file neither imports nor declares, whose import leads to no file, or whose class another context declares; a line of `NOT_LISTED` whose class is gone; a `LISTED` whose entries it cannot read (spread, or built by a call); and, once, a project on one of the four ORM that holds stores and no list. It does not judge an abstract class, a store in memory or in OpenSearch, a class over `TableReadModelStore` of the kernel, nor a base reached through a namespace or an import alias (`ddd-ts-kit explain persistence/read-model-listed`, [docs/concepts/cqrs.md](docs/concepts/cqrs.md#every-table-checked-at-the-start-and-before-a-deployment)).

`init` finds the stores by the same reading as the rule, on the sources as the checker reads them and no longer by a regular expression over class declarations. It now reads every source of a context, not its `infrastructure/persistence/` alone, follows a base class declared anywhere under the source root, skips the tests, and no longer takes a class written directly over `TableReadModelStore` for a store kept in a table. A store it cannot build is still named in `NOT_LISTED`; its note now says to write the class that builds it beside the store, where `init` lists it and `init --force` keeps it, and a store such a listed class extends is no longer named again.

To move: run `npx ddd-ts-kit check --rule persistence/read-model-listed`. For each store it reports, add the import and the entry its fix gives to `src/platform/database/read-model-tables.ts` (`npx ddd-ts-kit init` writes them), or leave the store out with a comment there that holds `<context>: <Store>` and the reason. A project generated before 0.112.0, which has no list: commit, then run `npx ddd-ts-kit init --force`.
