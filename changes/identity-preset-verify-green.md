**A project written with `--preset identity` passes its whole `verify`.** Two of its steps failed on a project just initialised: `test:coverage`, the branches of `identity/presentation` at 66.66% under their floor of 70% (the controller of `PUT /accounts/me` was never called by a token without an address, nor without a display name in the body), and `docs:check`, `openapi/openapi.yaml` written before the preset added its routes. The spec of that controller now covers both cases, and `init --preset` ends by saying `Run npm install, then npm run docs:generate (the routes and events of the preset are not in the contracts yet), then npm run verify`: the contracts are written from the running application, which only the project can build. The `bootstrap` skill runs `docs:generate` before `verify` after `generate context --preset`.

To move: a project written from the preset by 0.83.1 or earlier runs `npm run docs:generate` once and commits the contracts; its `verify` then fails only on the coverage of `presentation`, which the case `names the person after their username when the body names nothing, and sends no address the token lacks` of `provision-account.controller.spec.ts` covers.
