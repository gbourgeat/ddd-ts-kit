**The rules, the readers and the tool configuration of the CLI read a module that holds its tests (`<module>/test/`) and `shared/`, wherever they named a path of the context.** Nothing writes that layout yet, and the layout of today is read as before.

- `test/spec-required` and `test/builder-required` find a spec in `<module>/test/` and a builder in `<module>/test/builders/` or `shared/test/builders/`, and name the test folder of the module once it holds one; `test/acceptance-black-box` lets an acceptance spec import those builders; `module/complete` names `shared/<layer>/<role>` for a file of a module left in `shared/`.
- `ddd-ts-kit docs` writes the rules of the specs of `<module>/test/` on the behaviour page of their context, under the same headings as the specs of `test/unit/<module>/`, each named where it is; `describe` reads the route groups of `shared/presentation/http/` and of a module.
- `generate test-world` reads the fakes of every module and of `shared/`, and the world of `shared/test/worlds/`; `controllers` writes the route groups in `shared/presentation/http/` once the context holds it and moves a spec within `<module>/test/unit/`; `error-factories --apply` finds the spec of an error of a module in `<module>/test/unit/` or `test/unit/<module>/`, where it found it in `test/unit/` alone; `init --force` lists again a tables file of `shared/infrastructure/persistence/` and an erasure adapter of a module; `drizzle-generate` and `typeorm-generate` warn of the tables of `shared/` and of the modules a migration would drop.
- `ddd-ts-kit affected` reads a change of `<module>/test/` or `shared/test/` as a change of tests alone.
- The generated `.dependency-cruiser.cjs` holds `<context>/<folder>/test/` as test code, and the fakes and worlds there as files that may have no importer. The templates of a new project follow: `vitest.config.ts` (the integration specs), `vitest.mutation.config.ts`, `jest.mutation.config.js`, `knip.json` and `.claude/rules/tests.md` (with the Copilot instruction written from it) name `src/contexts/*/*/test/` beside `src/contexts/*/test/`.

To move: run `npx ddd-ts-kit depcruise-config --write` and commit `.dependency-cruiser.cjs`, which `depcruise-config --check` reports as stale until then. The other files change nothing until a module holds its tests; to follow them now, by hand: in `vitest.config.ts`, `const INTEGRATION_SPECS = ['src/contexts/*/test/integration/**/*.spec.ts', 'src/contexts/*/*/test/integration/**/*.spec.ts'];`, spread in the `exclude` of the unit project (`[...INTEGRATION_SPECS, ...NOT_AFFECTED]`) and given as the `include` of the integration one; in `vitest.mutation.config.ts`, add `'src/contexts/*/*/test/integration/**'` to `exclude`; in `jest.mutation.config.js`, the pattern `'/src/contexts/[^/]+/(?:test|[^/]+/test)/integration/'`; in `knip.json`, the entries `"src/contexts/*/*/test/fakes/*.ts"` and `"src/contexts/*/*/test/worlds/*.ts"`; in `.claude/rules/tests.md`, the path `"src/contexts/*/*/test/**"`.
