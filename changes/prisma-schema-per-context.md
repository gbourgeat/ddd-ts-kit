**On Prisma, each bounded context keeps its models in a file of its own, `prisma/schema/<context>.prisma`, which its worker changes with the mapper on its own branch.** A worker of `parallel-work` that added a state field to an aggregate needed a column, but `prisma/schema.prisma` held the models of every context and the guard refused it to the worker as a shared file: the conductor wrote the column on the trunk, where the mapper of the context had not changed, and the trunk failed to typecheck until the column was reverted. Drizzle, Knex and TypeORM already kept the tables of a context in its own `infrastructure/persistence/`; Prisma now does the same with its multi-file schema. `init --orm prisma` writes `prisma/schema/schema.prisma` (the generator of the client, the datasource and the tables of the platform: outbox, background jobs, process instances, event store, audit trail) and `prisma.config.ts` names the folder (`schema: './prisma/schema'`); `generate repository` writes the model in `prisma/schema/<context>.prisma`, started with the models region of the context, and adds the database schema of the context to the datasource on the first repository of the context only. The guard lets the worker of a context write `prisma/schema/<context>.prisma`, and refuses it the file of another context and `prisma/schema/schema.prisma`; `generate --local-only` treats it as a file of the context and `verify-slice` stages it with the slice; `worker-scope` briefs the worker on Prisma that the models of its context are its own, a stored field changing its column and the mapper in one commit. The identity preset lays its models out in `prisma/schema/identity.prisma`, `privacy/declared-field` and `persistence/no-file-content` read every `.prisma` file of `prisma/schema/`, and `db:client` derives the schema of the tests from the folder (`prisma migrate diff --to-schema prisma/schema`).

To move: in a project on Prisma, `mkdir prisma/schema && git mv prisma/schema.prisma prisma/schema/schema.prisma`; in that file write the `output` of the generator one level up (`"../../generated/prisma"`), and move the models and enums of each context (those whose `@@schema` is the schema of the context) out of the `// ddd-ts-kit:models` region into `prisma/schema/<context>.prisma`, between a `// ddd-ts-kit:models` and a `// /ddd-ts-kit:models` line of their own, then remove the empty region from the main file. In `prisma.config.ts` set `schema: './prisma/schema'`, and in the `db:client` script of `package.json` replace `--to-schema prisma/schema.prisma` by `--to-schema prisma/schema`. Run `npm run db:client`: the tables are the same, so `npm run db:generate` finds no change and no migration is needed.
