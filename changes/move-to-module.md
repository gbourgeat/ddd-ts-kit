**`ddd-ts-kit move-to-module <context> <module> <path>...` moves files of a context into a module of the model, with every import of them.** The paths are relative to the context, files or folders under `domain/` or `application/` (an aggregate, a use case folder); the module must be declared first (`generate module`, which the command names when it is not). Every import of a moved file is rewritten under the source root, `test/` and `scripts/`, by alias or relative path, the extension kept as written. `--dry-run` prints the plan, `--json` gives it as data. The generated declarations are rewritten in the same run, every file of a folder moves (not only its sources), a path already in a module moves to the other one, and the folders the move empties go. Nothing is moved when a file of the same name is in the module already, or when a file is not text. The checks and the tests come next.

To move: nothing; use it to divide a context into modules one cluster per commit, until `module/complete` warns no more.
