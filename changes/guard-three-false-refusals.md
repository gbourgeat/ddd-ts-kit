**The guard of the plugin no longer refuses three commands a worker may run inside its scope.** A folder of its context is moved, removed and copied into (`git mv <folder>`, `mv`, `rmdir`, `rm -r`, `cp file <folder>/`): the guard took a folder for a file with another name (a hard link), since a folder counts more than one link. The schema of a query string, `presentation/http/<resource>/<use-case>/*.query.ts`, is written by hand as `docs/ARCHITECTURE.md` says, in the presentation layer of a context alone (`<context>/presentation/`, `<context>/<module>/presentation/`, `<context>/shared/presentation/`): everywhere else a new `*.query.ts` is still sent to `generate query`. A command given a folder (`cp`, `mv`, `ln`, `install`, `rsync`) is judged by what it brings into it and by the files it lands on there: a link or a whole tree comes from the scope alone, a folder that holds a file with another name elsewhere takes nothing, and a file lands where its name leads; a folder past 5000 files takes none by these commands. `chmod`, `chown`, `chgrp`, `chattr` and `setfacl` are held to the scope as a command that writes the file is. And the words of the command behind a package runner (`npx`, `pnpx`, `bunx`, `npm exec`, `pnpm exec`, `pnpm dlx`, `bun x`) are read as the shell split them, so `npx ddd-ts-kit generate value-object invoicing SupplierName --term "SupplierName=le nom d'un fournisseur"` is no longer refused as a quote that never closes, nor a `>` or a `;` inside a quoted word read as a redirection or a second command. That holds for the one shape the guard reads in full: the runner, its subcommand, the options it knows (`-y`, `-p`, `-w`, `--filter`, `--dir` and their like), then a program named plainly and its arguments. Any other invocation may hand text to a shell (`-c`, `--call`, `--shell-mode`, an option the guard does not know, short options written together, `npm exe`, a setting such as `npm_config_call` on the line, `yarn`, `bun run`) and every word of it is read as shell text, as before.
