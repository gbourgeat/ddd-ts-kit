**The guard of the plugin no longer refuses three commands a worker may run inside its scope.** A folder of its context is moved, removed and copied into (`git mv <folder>`, `mv`, `rmdir`, `rm -r`, `cp file <folder>/`): the guard took a folder for a file with another name (a hard link), since a folder counts more than one link. The schema of a query string, `presentation/http/<resource>/<use-case>/*.query.ts`, is written by hand as `docs/ARCHITECTURE.md` says, in the presentation layer alone: everywhere else in a context a new `*.query.ts` is still sent to `generate query`. A command given a folder (`cp`, `mv`, `ln`, `install`, `rsync`) is judged by what it brings into it and by the files it lands on there: a link or a whole tree comes from the scope alone, a folder that holds a file with another name elsewhere takes nothing, and a file lands where its name leads. And the words of the command behind a package runner (`npx`, `pnpx`, `bunx`, `npm exec`, `pnpm dlx`) are read as the shell split them, so `npx ddd-ts-kit generate value-object invoicing SupplierName --term "SupplierName=le nom d'un fournisseur"` is no longer refused as a quote that never closes, nor a `>` or a `;` inside a quoted word read as a redirection or a second command; a runner asked for a shell is still read as a command line, on every runner: the string of `-c`/`--call` of `npx` and `npm exec` (`--call=...` too), the command of `pnpm exec`, `pnpm dlx` and `pnpx` under `-c`/`--shell-mode` wherever the option stands among pnpm's own, and `env -S` and `su -c`. `bun x`, `npm x` and a runner's options that take a value (`-w`, `--filter`, `--dir`) are read too.
