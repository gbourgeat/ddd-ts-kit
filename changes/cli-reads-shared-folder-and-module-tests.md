**`ddd-ts-kit check` reads the layout to come of a context divided into modules: each module holding its tests, and `shared/` for what belongs to no module.** In a context that declares modules of its model, `<module>/test/` (`unit/`, `integration/`, `builders/`, `fakes/`) is read as the test folder of that module, and `shared/` as the place of what the context keeps at its own level: `shared/infrastructure/persistence/` (its schema and tables), `shared/presentation/http/` (its route groups, `guards/` and `shared/`) and `shared/test/` (`worlds/`, `fakes/`, `builders/`). A file there has the role it has today at the level of the context, and no module: `tree/closed` holds both, closed (`shared/` has no `domain/` and no `application/`), and the rules that read a location (`naming/suffix`, `test/helper-placed`, `module/complete`, `module/no-cycle`) judge it as the same file at its place of today. Nothing writes this layout yet and the layout of today is read as before: the generators, `move-to-module`, `context-layout`, `test/spec-required` and `test/builder-required` follow in the next versions, with the documentation. `shared` is now the name of that folder and can no longer name a module: `config/valid` and `ddd-ts-kit generate module` refuse it and say why, where `module/declared` refused it as a technical word.
