**A read model on `@ddd-ts-kit/typeorm` leaves a column declared `select: false` out of the rows it answers.** The rows held every column of the entity but the stamps, so a read model of tenant data answered `tenantId` even when the row of its port did not carry it, where the stores of the three other ORM answer the mapped fields only. Declare the tenant column `tenantId: { ...tenantColumn().tenantId, select: false }` in an entity typed `Row & TenantScoped & ReadModelStamps`: the store still writes it and confines every statement to it. An entity that declares the column without `select: false` answers it as before.
