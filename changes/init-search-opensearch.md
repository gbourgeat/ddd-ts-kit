**`ddd-ts-kit init --search opensearch` wires the read models of OpenSearch in the platform.** The choice is recorded as `stack.search` (`none` by default, and for a config that does not say). `@ddd-ts-kit/opensearch` joins the dependencies; `src/platform/search/` hands every context `SearchIndexes`, whose `options(name, definition)` gives an `OpenSearchReadModelStore` the transport of `OPENSEARCH_URL` and the tenancy of the project (a filtered alias per tenant under `--tenancy shared-table`), and provisions the index of each store built from it before its first request; a project with no store calls nothing. `loadConfig` reads `OPENSEARCH_URL`, and `OPENSEARCH_USERNAME` with `OPENSEARCH_PASSWORD` both or neither; the compose stack runs one node, `.env.example` and the README name the variables. No generator writes a store yet: an adapter extends `OpenSearchReadModelStore` and calls `super(search.options('billing_invoices', criteria))`. The new rule `search/store-from-platform`, an error, refuses a context that names anything of the package but the store and its refusals, and an adapter whose code names a `tenancy`, a `strategy` or a `transport`, even over the answer of `search.options`. What fits a search read model and what does not, its tests, its tenants and its rights in production: `docs/tools/search-read-models.md`; each choice: `docs/adr/0009-init-wires-opensearch.md`.
