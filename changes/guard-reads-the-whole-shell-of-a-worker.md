**The guard reads the whole shell command of a worker, not only one that starts with `cd <worktree> && ...`.** The worker scope now applies to every command of a context-builder: a write that does not move into the worktree is refused with the instruction to run it as `cd <worktree> && ...`. The reader follows a `cd` only when it is certain (after `&&`, into a directory that exists), reads a name the shell computes (a variable, a substitution, a brace list), a wrapper (`nice`, `ionice`, `setsid`, `flock`, `busybox`, `su -c`, `env -S`), a package runner (`npx`, `npm exec`) and the command it runs, a double quote or a backquote inside `$(...)`, and the writers the file tables used to miss (`>&`, a `sed` or `awk` script that writes, `vim`/`ed`, `rsync`, `curl -o`, `wget -O`, `tar -x`, several `git` writers such as `stash`, `reset --hard`, `worktree add`, `checkout -f`, `eslint --fix`, `biome --write`). A worker's only free places outside its scope are `/dev/null`, the standard devices and the temporary directory (`$TMPDIR`); any other absolute place is refused. A command nested deeper than the reader follows (more than five shells or `eval`s) is refused rather than let through unread. A sub-agent is refused a `git config` that sets a value and a `git -c` of a key that runs a command in every checkout (`core.fsmonitor`, `core.pager`, `core.editor`, `core.sshCommand`, `alias.*`, a diff or filter driver), and the guard runs its own git with `core.fsmonitor` off. The same shell reading now holds the `domain-test-writer` to the paths of a test, the code of a story to its build gate, and every session's hand-writing of a generated file or the baseline, each judged by the places a command writes (a glob expanded) rather than its text; a Codex `apply_patch` sent through the shell is read as a patch.

To move: a worker's command after `cd dir;` is now refused; write `cd dir && ...`. A worker's write to a path outside every kit project is refused; use `$TMPDIR` for a scratch file.
