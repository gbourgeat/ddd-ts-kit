**A worker that merges an integration branch is no longer stopped by the guard of the plugin.** The guard took what a merge brought in for the trunk's only when the other side was on the branch `origin/HEAD` names, `main` or `master`: with workers cut from an integration branch (`worker-scope --base work/<plan>`), every file of that branch outside the scope of the worker was held as its own change after `merge-trunk`, each command and write was refused, and the refusal named `git checkout <commit> -- <path>` and `git rm`, which would have undone the trunk in the branch. The `base` that `.ddd-ts-kit/worker.json` records is now a trunk too, ahead of the three others, during the work and at the stop of the worker. It is read once, when the worker is pinned, with the base commit and the branch the file records, and a scope file whose base, base commit or branch changes afterwards stops the worker as one whose context changes does, until the conductor restores it. A base is a branch of the repository, local or of a remote, other than the worker's own; and a merge is the trunk's when a trunk held its other side before the command that merged it, so a trunk fetched and merged by one command (`git fetch origin && git merge origin/main`) is held: `npx ddd-ts-kit merge-trunk` merges it, or the fetch goes in a command of its own. A merge of a branch that is no trunk is still held, and the refusal then names no command: the worker undoes nothing and reports the merge to the conductor. The refusal of a file changed outside the scope reads "Your commands, or another session, changed files outside your scope", since the guard sees the change, not who made it.
