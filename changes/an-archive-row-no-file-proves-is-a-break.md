**An archive row that no file proves is the break of its chain.** The guard of the trail lets through the `DELETE` of an entry a row of `audit_archives` covers, so a role that may both insert such a row and delete entries can let entries go behind a row of its own. `verifyTrail(trail, { files })` now reads back the file of the last archive of each chain and proves it with `verifyArchive` before it verifies the entries left from its anchor: a row without its file answers `missing-entry`, a file that does not prove its row `altered-content`, at the first sequence the row names. `VerifyAuditTrail(trail, files)` passes the storage on. A generated project with a storage of files gives it to the nightly `audit.verify` and to `npm run audit:verify`. The documentation of the guard says which two privileges open that path, and that they belong to the role that archives.
