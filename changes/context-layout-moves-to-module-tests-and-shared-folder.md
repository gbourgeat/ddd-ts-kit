**`ddd-ts-kit context-layout` lays a context divided into modules out with its tests in its modules and `shared/` for what belongs to none, and `move-to-module` moves within that layout.** Nothing else writes that layout yet, and the layout of today is read and accepted as before: running the command is a choice.

- In a context that declares modules, `context-layout` moves, in one run: the specs of `test/unit/<module>/` and `test/integration/<module>/` to `<module>/test/`; a spec, a fake or a builder left in the test folders of the context to the module of the file it is named after (a builder after an aggregate, a fake after a port or a repository), else of the one module its imports name; what the context keeps at its own level to `shared/`: its schema and tables (`shared/infrastructure/persistence/`), its route groups, guards and shared shapes (`shared/presentation/http/`), its worlds, and the specs, fakes and builders no module is told for (`shared/test/`). A file of a layer whose imports name no module, or two, stays and is listed with the `move-to-module` command to run. A file already at its target is never overwritten, the pair is listed; run again, nothing moves.
- Every import follows, as before, and now also the compiled path a migration names a moved file by (`../dist/src/contexts/<context>/infrastructure/persistence/<name>.schema.js` in a Knex migration), for `move-to-module` too. The schema index of the platform follows as any import.
- The entries of `knip.json` that name the fakes and worlds of a context name those of its modules beside them; a `vitest.config.ts`, `vitest.mutation.config.ts` or `jest.mutation.config.js` that still names the integration specs of `<contexts>/*/test/integration/` alone is said, not rewritten.
- `move-to-module`, in a context laid out that way, writes a spec to `<module>/test/<unit|integration>/`, takes a fake or a builder to `<module>/test/`, moves a file out of `shared/` and from one module to another, and finds the specs named after a moved file where that file came from.
- `tree/closed` accepts `shared/test/unit/` and `shared/test/integration/`: the spec of a guard of `shared/presentation/http/guards/`, or of several modules, lives there.
