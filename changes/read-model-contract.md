**`readModelContract` of `@ddd-ts-kit/testing/contracts` holds the read model port of a context, on rows of its own.** `readModelStoreContract` runs on the fixed row of the kit and holds the table of an ORM package; nothing held the port a context declares over it, so its fake and its adapter were compared by hand. `readModelContract<Row>(runner, { name, createStore, createRow, change })` runs the same cases on any `ReadModelStore<Row>`: a row read back as written, nothing for an unknown key or for a change that answers nothing, an event delivered twice or older than the row ignored, a deletion an older event does not undo, a search that lists the rows held and none removed, and with `change` the current row handed to a later event (pending without it). `ddd-ts-kit generate read-model` writes the spec that runs it on the fake and on the adapter.
