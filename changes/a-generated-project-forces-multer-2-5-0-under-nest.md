**A project generated on Nest forces multer `^2.5.0`, and one on Fastify asks for `fastify` `^5.12.7`.** `@nestjs/platform-express`, up to 12.2.0, asks for multer 2.4.0 exactly, open to a denial of service through a pending `fileFilter`: `init --http nest` forces 2.5.0 in `overrides` of `package.json` under npm, and of `pnpm-workspace.yaml` under pnpm, which reads nothing of `package.json`. An override the project already sets for multer is kept, and said, unless `--force`. Fastify 5.12.2 to 5.12.5 let a request header go around the validation of a schema whose `propertyNames` reads it by case (low severity).

To move: in a project on Nest, `npx ddd-ts-kit init` writes the override (or add `"overrides": { "multer": "^2.5.0" }` to `package.json` under npm, `overrides:` with `multer: '^2.5.0'` to `pnpm-workspace.yaml` under pnpm), then install again. In a project on Fastify, install `fastify@^5.12.7`.
