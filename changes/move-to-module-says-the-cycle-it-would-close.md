**`ddd-ts-kit move-to-module` writes nothing when the move would close a cycle between modules, and says which.** The command moved the files and rewrote their imports, and `module/no-cycle` reported the cycle afterwards. It now reads the imports between the modules of the context as the rule does, before the move and with the move planned, and refuses a move that makes a module import another that imports it back, directly or through a third: the refusal names the cycle, each step of it with its imports (file and line, the steps the move adds told apart from the ones there now), and the file at the other end of the imports the move adds, to move along in the same command. `--dry-run` refuses with the same words. The new `--allow-cycle` moves all the same and says the cycle with the move, in the text and under `cycles` of `--json`. A cycle that is there before the move is not counted, and a project that turns `module/no-cycle` off is not judged. `context-layout` is unchanged: it already leaves where it is a file that would make a module depend on another.
