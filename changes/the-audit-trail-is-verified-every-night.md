**The audit trail of a generated project is verified every night.** `verifyTrail(trail)` of `@ddd-ts-kit/audit` verifies every chain, each from the anchor of its last archive to its head, so a chain cut at its tail does not verify, and answers the first break of each chain with the number of entries examined; `VerifyAuditTrail` is the scheduled job that runs it and fails with `AuditTrailBrokenError` (`breaks`, code `AUDIT_TRAIL_BROKEN`) on a break. `ArchivableAuditTrail` gains `chainHeads()`, the sequence and the hash of the last entry of every chain, on the four SQL stores and on `InMemoryAuditTrail`. With the trail on, `init` registers the platform job `audit.verify` every night at 04:30 UTC, in the three families of dependency injection, switched off with `JOB_AUDIT_VERIFY_ENABLED=false`; with the trail in a database it writes `scripts/audit-verify.ts`, run by `npm run audit:verify`, exit code 1 on a break. The factory of the store moves to `src/platform/audit/create-audit-trail.ts`, which the script shares with the platform.

To move: `init --force` rewrites `src/platform/audit/create-audit.ts`, writes `create-audit-trail.ts` and `scripts/audit-verify.ts`, and rewrites the composition and `jobs/job-settings.ts`. On tsyringe, `auditModule(audit, { jobs })` always takes `jobs`. A store of your own that implements `ArchivableAuditTrail` adds `chainHeads()`.
