**The guard notes every run of code a worker starts, not only its inline code, and pins the worker's scope at its first call.** Before each command of a context-builder that runs code the guard cannot read (a script it wrote, `bash x.sh`, a shell fed on its input or given `-lc`, `source`, `make`, `tsx -e`, `node -r`, `npm test`, `npm run`, `npx`, any interpreter or package runner), every command but the pure readers (`cat`, `ls`, `grep`, `git log`, `git status`...), the guard notes the state outside the scope and compares it at the worker's next call: the `git status` and `HEAD` of the worktree, so that a commit of the code, an amend or a reset is seen too; the checkout of the session when it is another, whose change is said once for the conductor; and the manifest and bin of the kit's CLI and of Biome in `node_modules`, the files the guard runs, whose change is said once too. A deletion is now a change, and the guard names the state a file is held to with the command that gets there: its committed content (`git checkout <commit> -- <path>`, then `git commit` when a commit changed it), the content it had before the command when it was already changed (kept under `.ddd-ts-kit/guard/held/`), `git mv` back for a rename, `rm` for a new file. The scope of a worker (its context and its worktree) is recorded at its first call in the guard's folder of the session's checkout: a `.ddd-ts-kit/worker.json` removed or changed afterwards, or the worktree of another worker, is refused with "the scope file changed: report to the conductor". The shell reader reads a combined short flag of a shell (`bash -lc`, `bash -ec`) as `-c`, and a builder's code run from the conductor's checkout without `cd <worktree> &&` is refused. Other git-ignored files and places outside these checkouts are still not enumerated, as the guide and the hooks' description now say (see docs/guides/agent-sandbox.md to isolate an agent).

To move: a worker's `npm test` or script run now costs a `git status` before it (two when it works from the conductor's checkout); a worker whose scope file is removed is refused until the conductor restores it.
