**Breaking: a read model refuses a stamp with a version under a key that holds one without, and the reverse, and a conditional replace compares the version on every store.** `isNewer` of `@ddd-ts-kit/kernel` compared versions when both stamps carried one and instants otherwise, which is not an order: with A (version 1, 12:09), B (no version, 12:05) and C (version 2, 12:01), C was newer than A, A newer than B and B newer than C, so the row a key ended on depended on the order of the deliveries. A version counts the events of a key and an instant reads a clock: neither says where the other stands, and a rule that ranked one kind above the other would drop events in silence. `isNewer(incoming, held, key?)` now throws `MixedStampsError` (with `incoming`, `held` and the `key` when given) for one stamp of each kind, and every write of a read model (`upsertIfNewer`, `updateIfNewer`, `delete`, the copy of a rebuild) refuses it by the name of the key. Within a kind the order is total, as it was: by version, or by instant then event id. A mix was real: a projection that passed a version on some events of a key only, a source of a rebuild that stamped its rows with an instant while the events carried a version, a spec that seeded a row with a bare stamp. `sameStamp(left, right)` is exported: the equality a conditional replace uses, the event id, the instant and the version. The in-memory table and `@ddd-ts-kit/opensearch` compared the three; `@ddd-ts-kit/knex`, `@ddd-ts-kit/drizzle`, `@ddd-ts-kit/prisma` and `@ddd-ts-kit/typeorm` compared the event id and the instant alone, so a row whose version alone had moved (two domain events of one name and one aggregate in the same millisecond share both) was replaced by a write computed from the row before it. The four now compare the version too, NULL matching NULL. `readModelStoreContract`, `readModelRowsContract` and `readModelContract` of `@ddd-ts-kit/testing` hold it: the same row whatever the order of three deliveries, for each kind, the refusal of a mix, and a replace refused on a stamp whose version differs. See `docs/concepts/cqrs.md`, "Which write for which event".

To move: stamp every event that writes one key the same way, `stampOf(event, version)` on all of them or `stampOf(event)` on all of them, and give the rows of the `ReadModelSource` of a rebuild stamps of that kind; a spec or a fake that seeds a row stamps it as its projection does. A read model that goes from one kind to the other is emptied (its traces included) and rebuilt, since the rows it holds carry the old kind. A `MixedStampsError` in the dead letters of a consumer names the key and the two events to look at. A `ReadModelRows` of your own compares the version in `replace`, with `sameStamp`. Run `readModelStoreContract` again on your stores.
