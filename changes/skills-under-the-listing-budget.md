**The descriptions of the skills fit the listing budget of Claude Code, so every skill keeps its triggers; the skills read the text of `describe` and `list`; and the merge of the trunk and the review remarks are each stated in one skill.** Claude Code loads the name and description of every skill into each session within 1% of the context window (about 8,000 characters on a 200k window) and, when the listing overflows, drops the descriptions of the skills invoked least: the 26 descriptions of the plugin took 13,853 characters, so on a 200k window some skills stopped triggering on their keywords. Each description now opens with its trigger ("Use when ..."), keeps the words a user says for it and leaves the pointers to other skills to the body: 7,489 characters for the 26, from 259 to 352 each, and the 6 agents from 2,768 to 2,166 characters. A test of the plugin (`node --test plugin/skills/descriptions.test.mjs`) fails on a skill or agent description over 400 characters, or on 26 skill descriptions over 8,000 together, and names them.

The skills and agents now read the text of `npx ddd-ts-kit describe <context>` and `npx ddd-ts-kit list`, the better map for an agent and a third of the size of their `--json` (14.8 KB against 45.8 KB for `describe` on the example), which stays for a script.

Bringing the trunk in with `merge-trunk` is stated in the parallel-work skill ("Bring the trunk in"), and the `TODO(review)` lines and the rule of two in the quality-gate skill ("Review remarks"); the story skill, the quality-gate table and the architecture-reviewer agent say it in one line and point there, the commands printing their next step on each stop.
