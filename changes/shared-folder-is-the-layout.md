**Breaking: a context divided into modules keeps no layer folder and no `test/` folder at its root; each module holds its tests, and `shared/` holds what belongs to none.** A part of the model is one folder, its tests with it; what several modules share has one place. A context without modules is unchanged.

- The layout: `<module>/domain/` to `<module>/presentation/` and `<module>/test/` (`unit/`, `integration/`, `builders/`, `fakes/`); `shared/infrastructure/persistence/` (the schema and tables of the context), `shared/presentation/http/` (its route groups, `guards/`, `shared/`) and `shared/test/` (its worlds, and the fakes, builders and specs of no module). A builder follows the aggregate it is named after and a fake the port or the repository it is named after, into their module. `shared/` holds no `domain/` and no `application/`, is never declared in the config, and no module may be named `shared`.
- `ddd-ts-kit generate` writes that layout and nothing else: a spec, a fake and a builder in `<module>/test/` (`generate builder` now takes `--module`), a schema, a route group, a guard, a shared shape and a world in `shared/`. It refuses a context that still holds `test/` at its own level, and names `context-layout`.
- `module/complete` reports `test/` at the level of a context that declares modules, and a layer folder there that holds nothing but what `shared/` holds now, as an error whatever its severity, one finding per folder. A file of a layer still at the level of the context, or a file of a module left in `shared/`, stays a warning: a context that gains its first module moves one cluster per commit with `move-to-module`, read as it is meanwhile.
- `move-to-module` takes a spec, a fake or a builder to `<module>/test/`, from the level of the context, from `shared/` or from another module.
- `controllers` refuses to turn a function route that sits in `shared/presentation/http/`: a route belongs to a module, and the command names the `move-to-module` to run first.
- The layout of 0.86 and 0.87, a module under `domain/<module>/` and `application/<module>/`, is no longer read, by the CLI nor by `@ddd-ts-kit/eslint-plugin`: a project still laid out that way runs `context-layout` of 0.109 first.

To move: `npx ddd-ts-kit context-layout`, then `npx ddd-ts-kit depcruise-config --write`, the formatter, the checks and the tests. The command moves, in each context that declares modules, the specs of `test/<unit|integration>/<module>/` to `<module>/test/`, each spec, fake and builder left in the test folders of the context to the module of the file it is named after, else of the one module its imports name, else to `shared/test/`, and the schema, the route groups, guards and shared shapes and the worlds to `shared/`, with every import of them and the compiled path a migration names them by. It leaves to a person, and lists: a file of a layer whose imports name two modules, or none (`ddd-ts-kit move-to-module <context> <module> <path>`); a file already at its target, which it never overwrites; and each `vitest.config.ts`, `vitest.mutation.config.ts` or `jest.mutation.config.js` that still names the integration specs of `src/contexts/*/test/integration/` alone, where `src/contexts/*/*/test/integration/` goes beside it. `ddd-ts-kit check --rule module/complete` lists the folders still to move.
