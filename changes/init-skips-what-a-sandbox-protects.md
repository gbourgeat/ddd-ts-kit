**`init` no longer stops midway when a sandbox protects a path: it writes every other file and gives the command to finish.** Under the sandbox of Claude Code, which the regulated profile turns on, the agent cannot write `.claude/settings.json` nor `.claude/hooks/`, and `init` stopped with `EEXIST` after part of its files, leaving a project that could not be verified. It now leaves out each file it cannot write, lists it under `unwritable` (and in `skipped`) of its report, a dry run included, and ends with a note that gives the same `init` to run from a terminal outside the sandbox: it writes the missing files and keeps the ones written. A file the sandbox masks with a device is reported as unwritable, no longer as an existing file to keep. Every command that writes files reports a protected path the same way. The `bootstrap` skill hands the real `init` and `npm run hooks:install` to the owner in a sandboxed session: the agent runs the dry run and shows the command, the owner runs `init`, the agent resumes at `npm install`, and the owner installs the git hooks before the first commit.
